## Системная модель

```text
Бизнес-запрос
  -> Проект / ProblemState
  -> Цель / Objective
  -> Корневая задача
  -> Иерархический граф задач
  -> Доменные расширения в слотах
  -> Контроллер допуска
  -> Механизм выбора задачи
  -> Манифест контекста
  -> Исполнение
  -> Артефакт
  -> Валидация / проверки качества
  -> Уточнения / допущения / эскалации
  -> Обновление ProblemState
  -> Раскрытие графа
```

## Компоненты

| Компонент | Ответственность |
|---|---|
| Реестр | Хранит YAML DSL: цели, шаблоны задач, контракты артефактов, доменные пакеты, методологические пакеты, проверки качества. |
| Хранилище ProblemState | Хранит текущее понимание проекта: факты, пробелы, готовность, решения, активные домены и методологии. |
| Хранилище графа задач | Хранит дерево задач, статусы, связи и события. |
| Координатор планирования | Раскрывает граф, применяет доменные расширения, проверяет допуск, выбирает следующую задачу. |
| Контекстный движок | Собирает воспроизводимый контекст для конкретной листовой задачи. |
| Среда исполнения | Выполняет листовую задачу через LLM, скрипт, инструмент, человека или гибридного исполнителя. |
| Хранилище артефактов | Хранит неизменяемые артефакты и производные представления. |
| Валидация и управление качеством | Проверяет артефакты, проверки качества, исправления и эскалации. |
| Координатор уточнений | Превращает кандидаты вопросов в допущения, пользовательские уточнения или эскалации по политике проекта. |
| Рабочее пространство UI | Показывает граф задач, ситуацию, историю, артефакты и технические детали. |

## Источники истины

| Область | Источник истины |
|---|---|
| Объекты реестра | YAML в Git |
| Граф задач | журнал событий задач + проекции |
| Состояние проекта | журнал событий ProblemState + снимок |
| Артефакты | хранилище неизменяемых артефактов |
| Контекст | манифесты контекста |
| Исполнение | запуски и трассы исполнения |
| Валидация | запуски валидации, замечания и проверки качества |
| Уточнения | журнал уточнений, ответов, допущений и эскалаций |

## Инварианты

| ID | Правило |
|---|---|
| A1 | Система не использует линейный маршрут как источник истины. |
| A2 | Цель задает критерии завершения, но не порядок работ. |
| A3 | Композитная задача раскрывается в подзадачи и слоты, но не исполняется как листовая. |
| A4 | Листовая задача выполняет одно небольшое действие и имеет проверяемый результат. |
| A5 | Доменный пакет расширяет дерево только через объявленные слоты. |
| A6 | Допуск к запуску детерминирован и не использует LLM. |
| A7 | LLM может ранжировать только уже допустимые задачи. |
| A8 | Исполнение получает данные только через `ContextManifest`. |
| A9 | Провал валидации должен быть виден пользователю и блокировать соответствующую область. |
| A10 | Архивные документы не имеют нормативной силы. |
| A11 | Исполнитель не задает вопрос пользователю напрямую, а возвращает кандидаты уточнений. |
| A12 | Пользовательское уточнение блокирует только явно указанную область графа. |
| A13 | Методология рассуждения накладывается на leaf-задачу через runtime wrapper и не зависит от шаблонов задач и доменных пакетов. |
| A14 | Методология и домен — независимые оси расширения. Конфликт по полю `reasoning_artifact` запрещён. |
