# Планирование

> **Статус:** v2.1 · черновик · 2026-05-09

Координатор планирования управляет динамическим графом задач: раскрывает задачи, применяет доменные расширения, проверяет допуск к запуску и выбирает следующую допустимую листовую задачу.

---

## Части планировщика

```text
Координатор планирования
  Сервис раскрытия графа
  Контроллер допуска
  Механизм выбора задачи
  Интеграция с координатором уточнений
```

### Раскрытие графа

Создает новые узлы:

- корневую задачу из цели;
- базовые дочерние задачи из композитных шаблонов;
- доменные расширения в слотах;
- задачи исправления;
- задачи обработки ответа пользователя, если ответ требует отдельной работы.

Раскрытие всегда идемпотентно.

### Контроллер допуска

Проверяет, можно ли запускать листовую задачу сейчас.

Проверки:

- статус задачи;
- статус родительской задачи;
- жесткие зависимости;
- обязательные поля состояния;
- обязательные артефакты;
- обязательные доменные пакеты;
- блокирующие пробелы;
- открытые блокирующие уточнения в области задачи;
- доступность контекста;
- доступность исполнителя;
- отсутствие дубля по стабильному ключу.

Допуск не использует LLM.

### Механизм выбора задачи

Выбирает одну задачу из допущенных к запуску.

Может использовать:

- детерминированную оценку;
- LLM-ранжирование уже допущенных задач;
- ручное решение оператора.

LLM не может добавить новую задачу или выбрать заблокированную задачу.

---

## Цикл планирования

```text
1. Загрузить `ProblemState`.
2. Загрузить снимок реестра.
3. Загрузить граф задач.
4. Раскрыть граф.
5. Пересчитать допуск к запуску.
6. Ранжировать допущенные задачи.
7. Выбрать следующую задачу или сообщить о блокировке/завершении.
8. Записать `PlanningDecision`.
```

## PlanningDecision

```python
class PlanningDecision(BaseModel):
    decision_id: UUID
    project_id: UUID
    selected_task_id: UUID | None
    status: Literal["selected", "blocked", "objective_completed", "no_ready_tasks"]
    admitted_task_ids: list[UUID]
    blocked_task_summaries: list[dict]
    blocking_clarification_ids: list[UUID]
    ranking_strategy: Literal["deterministic", "llm", "operator_override"]
    rationale: str
```

Decision должен объяснять:

- какие задачи были допустимы;
- почему выбрана конкретная задача;
- почему остальные заблокированы;
- какие доменные расширения были применены.
- какие уточнения блокируют продолжение, если они есть.

---

## Уточнения в планировании

Планировщик не решает сам, какой вопрос задавать пользователю. Он работает с результатом координатора уточнений.

Правила:

- `ClarificationCandidate` не блокирует задачу сам по себе;
- блокирует только открытый `ClarificationRequest` с `blocking_scope`;
- неблокирующее допущение не мешает выбирать другие допустимые задачи;
- если все допустимые задачи заблокированы уточнениями, `PlanningDecision.status` становится `blocked`;
- после ответа пользователя планировщик пересчитывает допуск и раскрытие графа;
- если ответа достаточно для новой доменной области, доменные расширения применяются через обычный механизм слотов.

Если планировщик не находит доступных задач из-за недостающих вводных, он создает не задачу-вопрос напрямую, а кандидат уточнения с объяснением причины блокировки.

## Завершение

Цель завершена, если:

- корневая задача завершена;
- обязательные артефакты доступны;
- обязательные проверки качества пройдены;
- нет блокирующих пробелов по критериям завершения цели;
- нет обязательных задач в ошибке в активном поддереве.

Композитная задача завершена, если:

- обязательные дочерние задачи завершены или корректно пропущены;
- обязательные артефакты поддерева доступны;
- обязательные проверки качества пройдены;
- нет блокирующих дочерних ошибок.

## Инварианты

| ID | Правило |
|---|---|
| PL1 | Планировщик не работает с линейным маршрутом. |
| PL2 | Раскрытие графа идемпотентно. |
| PL3 | Доменное расширение применяется только в существующий слот. |
| PL4 | Допуск к запуску детерминирован. |
| PL5 | LLM участвует только после допуска к запуску. |
| PL6 | Заблокированная задача имеет машиночитаемую причину. |
| PL7 | Завершение цели определяется проверками качества, артефактами и состоянием, а не отсутствием следующего шага. |
| PL8 | Открытый вопрос пользователя блокирует только свой `blocking_scope`. |
| PL9 | Смена активного `methodology_pack` не меняет состав задач, но требует пересчёта допуска к запуску для уже допущенных leaf-задач. |
