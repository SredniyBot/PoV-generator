# Доменные пакеты

> **Статус:** v2.1 · черновик · 2026-05-09

Доменный пакет — подключаемый пакет доменных знаний. Он расширяет граф задач через доменные расширения в слотах.

`domain_pack` отвечает за **«над чем думаем»** и не зависит от `methodology_pack`, который отвечает за **«как думаем»**. Это две независимые оси расширения. Конфликт по полю, попадающему в `reasoning_artifact`, запрещён и считается ошибкой валидации реестра.

---

## Состав

Доменный пакет может содержать:

- сигналы обнаружения;
- шаблоны задач;
- контракты артефактов;
- проверки качества;
- доменные расширения в слоты;
- ожидания для валидации.
- политики и темы уточнений.

Доменный пакет не задает линейный маршрут и не вставляет «блок шагов».

---

## Пример

```yaml
kind: domain_pack
id: ml.predictive_analytics
version: 1.0.0
title: Предиктивная аналитика и ML

detect:
  signals:
    - прогноз
    - машинное обучение
    - скоринг

contributes:
  - to: data.entities
    add:
      - id: prediction_target
        task: ml.define_prediction_target@1.0.0
      - id: label_definition
        task: ml.define_label@1.0.0

  - to: data.quality
    add:
      - id: label_quality
        task: ml.assess_label_quality@1.0.0

  - to: solution.evaluation
    add:
      - id: model_metrics
        task: ml.define_model_metrics@1.0.0

  - to: review.domain_gates
    add:
      - id: ml_requirements_review
        gate: ml.requirements_complete@1.0.0

clarification_policy:
  topics:
    - id: ml.target_event
      title: Целевое событие прогноза
      ask_when:
        - missing_owner_decision
        - conflicting_goal
    - id: ml.model_usage
      title: Использование прогноза в процессе
      ask_when:
        - high_impact_low_confidence
```

## Слоты

Slot — публичная точка расширения композитной задачи.

Примеры:

```text
request.domain_signals
data.entities
data.quality
data.privacy
solution.evaluation
solution.explainability
spec.domain_sections
review.domain_gates
```

Если домену нужен новый слот, нужно выпустить новую версию соответствующего композитного шаблона.

---

## Активация

Поток:

```text
найден доменный сигнал
  -> кандидатный доменный пакет
  -> решение об активации
  -> активный доменный пакет в ProblemState
  -> раскрытие графа применяет доменные расширения
```

Источники активации:

- явный выбор пользователя;
- задача обнаружения домена;
- артефакт с сигналами;
- operator override.

---

## Правила доменного расширения

Доменное расширение:

- указывает `to`;
- добавляет `task` или `gate`;
- имеет стабильный `id`;
- применяется идемпотентно;
- может иметь детерминированное условие `when`.

Условия доменного расширения не должны требовать LLM.

---

## Доменные уточнения

Доменный пакет может расширять механизм уточнений так же, как он расширяет граф задач.

Он может добавлять:

- темы, по которым обычно нужны уточнения;
- доменные причины обязательного вопроса;
- варианты ответа;
- связи между вопросами, доменными задачами и проверками качества;
- правила, когда допустимо принять доменное допущение.

Пример:

```yaml
clarification_policy:
  topics:
    - id: security.personal_data
      title: Персональные данные
      ask_when:
        - security_or_legal_risk
      default_blocking_scope: subtree
```

Доменный пакет не показывает вопрос пользователю напрямую. Он добавляет знание, а координатор уточнений решает, нужно ли спрашивать с учетом режима участия пользователя и текущего состояния проекта.

## Типовые домены

ML:

- сущности данных;
- качество данных;
- оценка решения;
- доменные разделы ТЗ;
- проверки качества.

Security:

- приватность данных;
- ограничения решения;
- эксплуатационные операции;
- раздел требований безопасности;
- проверки качества.

Integration:

- системы-источники;
- обновление данных;
- выходы решения;
- эксплуатационные операции;
- раздел интеграционных требований.

Frontend:

- пользователи и заинтересованные стороны;
- выходы решения;
- раздел UI/UX в ТЗ;
- проверки согласованности.

## Инварианты

| ID | Правило |
|---|---|
| DP1 | Доменный пакет расширяет только объявленные слоты. |
| DP2 | Идентификатор доменного расширения стабилен и идемпотентен. |
| DP3 | Активация домена фиксируется в `ProblemState`. |
| DP4 | Планировщик не содержит жестко зашитых веток под домены. |
| DP5 | Доменное качество проверяется через проверки качества и контракты. |
| DP6 | Домен может встраиваться в разные композитные задачи. |
| DP7 | Доменный пакет может расширять уточнения, но не обходит координатор уточнений. |
| DP8 | `domain_pack` и `methodology_pack` — независимые оси; пересечение по полям `reasoning_artifact` запрещено. |
