⏺ У тебя уже всё установлено (.venv есть, node_modules тоже — мы их использовали
   в сессии). Опишу два сценария: быстрый CLI-смок и полноценный UI-прогон.

  1. Быстрый CLI-смок (stub-провайдер, без сети, ~30 сек)

  Это проверит, что архитектурный поток работает целиком: objective → 4 leaf'а →
   composite → готовый architecture.design_document в SQLite.

  cd /Users/gregorlov/PoV-generator
  source .venv/bin/activate

  # 1) Свежий workspace для эксперимента (не трогаем существующие)
  rm -rf runtime/arch-smoke && mkdir -p runtime/arch-smoke

  # 2) Создать проект на архитектурном objective
  povgen project init \
    --workspace runtime/arch-smoke \
    --name "Архитектура: онлайн-счётчики" \
    --objective architecture.system_design@1.0.0 \
    --request-text "Онлайн-сервис подачи показаний счётчиков с интеграцией в 1С:
   личный кабинет, мобильное приложение, REST API для УК."

  # 3) Прогнать весь граф до блокировки (stub-провайдер по умолчанию)
  povgen workflow run-until-blocked --workspace runtime/arch-smoke

  # 4) Достать финальный артефакт
  povgen artifacts list --workspace runtime/arch-smoke
  povgen artifacts show --workspace runtime/arch-smoke \
    --role design_document --format markdown | head -80

  Что ожидать:
  - На шаге 3 пройдут 4 leaf-задачи + composite synthesis, не задавая вопросов
  (стабы заполняют default_assumption).
  - На шаге 4 увидишь markdown с тремя fenced mermaid блоками (flowchart
  context, flowchart components, sequenceDiagram interactions).

  2. Полный прогон через UI (с Mermaid-диаграммами)

  Два терминала:

  Терминал A — backend:
  cd /Users/gregorlov/PoV-generator
  source .venv/bin/activate
  povgen-api --reload                            # :8788

  Терминал B — frontend:
  cd /Users/gregorlov/PoV-generator/ui/workspace
  npm run dev                                    # :5173 (проксит /api и /ws на 
  :8788)

  Открой http://localhost:5173:

  1. New project → имя любое, Objective = architecture.system_design@1.0.0, в
  business_request — любое описание системы.
  2. На L1 Mission Control нажми Run until blocked (или дай прогнать
  автоматически — workflow run-until-blocked под капотом).
  3. Когда задача design_synthesis закроется, появится артефакт
  architecture.design_document@1.0.0 — открой его.
  4. В правой панели (ArtifactDetailPanel) три блока mermaid должны
  отрендериться как графика, не как код.
  5. Нажми Download PDF — в PDF диаграммы останутся как preformatted code (это
  сознательное решение MVP, server-side SVG в roadmap §7).

  3. Сравнение с ТЗ-потоком (regression check)

  Создай второй проект на том же бизнес-запросе, но
  objective=common.requirements_specification@1.0.0. Прогони. Должен получиться
  нормальный ТЗ-документ — это доказывает, что архитектурная ветка не сломала
  старый поток.

  4. Если хочется живой LLM вместо stub'а

  UI → /settings → добавь провайдера (OpenRouter, Claude SDK с API-ключом, или
  Claude Subscription с локальным claude CLI после claude login). Потом в
  проекте — Set provider → выбери его и снова Run until blocked. Stub-фикстуры
  рассчитаны на детерминированный тест, но валидны как payload — реальная модель
   выдаст содержательнее.

  5. Откатить / переключить objective на проекте

  API:
  # Сменить методологию на проекте (если хочешь lean_jtbd на архитектуре или 
  наоборот)
  curl -X POST
  http://localhost:8788/api/projects/<project_id>/commands/set-methodology \
    -H 'Content-Type: application/json' \
    -d '{"methodology_pack_ref": "process.descriptive_decomposition@1.0.0"}'

  Чистый сброс:
  rm -rf runtime/arch-smoke   # стереть workspace целиком
